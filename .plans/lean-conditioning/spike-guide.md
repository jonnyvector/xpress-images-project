# lean-conditioning — Spike Guide

Operator-gated probes that fix the lean tail's composition BEFORE the
ladder is implemented (RFC-01 §5, D-009). The operator's eye is the
verdict; the identity judge is advisory at this sample size.

## Assumptions

### A-001: bare lean fixes coarse geometry without the anchor
- **Impact if false:** anchored draws lead the lean tail (M3 mix flips;
  escape hatch 1).
- **Experiment:** Journey and Dylan, 3 bare-lean draws + 3 lean+anchor
  draws each (temp 0, `rtf_minimal` prompt text, empty notes; anchor =
  the door's catalog `profile/3d-profile.jpg`). El Dorado's existing
  record (bare lean judge-clean on roll 4/5; lean+anchor 0/2 by judge)
  counts as prior evidence. Scratchpad probe script, read-only on
  projects — pattern: `probe_lean.py` (2026-07-08).
- **Pass criteria:** for each door, at least one bare-lean draw the
  OPERATOR accepts as profile-identical; anchored draws not visibly
  better on the failing dimension (frame width).
- **Effort:** ~30 min + ~$1.60 new spend (12 draws).

### A-002: the lean tail holds frame width without the spec note
- **Impact if false:** lean tail keeps ONLY the spec-file width note
  (escape hatch 2; OQ-2 option b).
- **Experiment:** same bare-lean draws as A-001, judged specifically on
  frame width vs the source (Journey/Dylan are the doors whose width
  note lifted siblings 2→4).
- **Pass criteria:** operator sees no frame fattening on the accepted
  bare-lean draws.
- **Effort:** none extra (same draws, one extra check).

## Outputs

1. `plan-db validate-assumption` for A-001/A-002 (pass/fail + evidence).
2. Tail-mix decision recorded (`record-decision`) and mirrored into
   implementation.md M3.
3. Spike report (`.plans/lean-conditioning/artifacts/spike-report.md`):
   per-draw table (door, rung, judge verdict, operator verdict), the
   comparison artifact link, and the decided mix.
